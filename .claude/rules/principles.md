# 全体の決まりごと

- **機能の範囲は自分用でよいが、性能・セキュリティ・可用性は一般公開するサービスの水準で作る。** 件数に上限のない一覧や読み込みを作らない（ページネーションや LIMIT を必ず付ける）、データは必ずユーザー単位で絞る、入力の長さ・件数に上限を設ける、重複などの整合性は DB の制約でも守る、重くなりうるクエリには時間の上限を付ける。
- **コードコメントは書かない。** Ruby・JS・SCSS・YAML・スキーマ・SQL すべて。意図は命名とコードの構造で表す。Rails やツールが生成したファイルに元からあるコメントはそのままでよい。
- **テストするのは外から見える振る舞い（public メソッドの戻り値、バリデーション、ジョブの実行結果、API の応答）だけにする。** コールバックで更新される列や private メソッドなど、内部の実装を直接検証する spec は書かない（実装を変えるたびに壊れて保守できなくなるため）。
- **`CLAUDE.md` と `.claude/rules/` には、常に守る方針・コアなテーブルとドメイン知識だけを書く。** 個別の機能の仕様と、既存のコードを踏襲すれば分かること（命名・置き場所・書き方の型など）は書かない。
