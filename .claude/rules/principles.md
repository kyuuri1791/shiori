# 全体の決まりごと

- **機能の範囲は自分用でよいが、性能・セキュリティ・可用性は一般公開するサービスの水準で作る。** 件数に上限のない一覧や読み込みを作らない（ページネーションや LIMIT を必ず付ける）、データは必ずユーザー単位で絞る、入力の長さ・件数に上限を設ける、重複などの整合性は DB の制約でも守る、重くなりうるクエリには時間の上限を付ける。
- **コードコメントは書かない。** Ruby・JS・SCSS・YAML・スキーマ・SQL すべて。意図は命名とコードの構造で表す。Rails やツールが生成したファイルに元からあるコメントはそのままでよい。
- **PORO は module ではなく class で書く。** `module_function` で関数を並べる形にしない（Rails の都合で module が必要なヘルパーや concern、名前空間は除く）。
- **テストは RSpec。** minitest は使わない。spec は `spec/` 以下に置く。テストデータは factory_bot（`spec/factories/`）で作り、spec のトップレベルにヘルパーメソッドを定義しない（前提は `let!` / `before`、対象は `subject` で書く）。遅延評価は分かりにくいので `let` ではなく `let!` を使う。`subject` は前提のデータを作り終えてから評価したいので遅延評価のままにする。
- **`CLAUDE.md` と `.claude/rules/` には、コーディングルール・常に守る方針・コアなテーブルとドメイン知識だけを書く。** 個別の機能の仕様（画面の配置や細かい動き、並び順の細部、具体的な回数の上限など）は書かない。それはコードとテストで表す。
